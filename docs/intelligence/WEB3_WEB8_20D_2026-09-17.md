## 2026-09-21 fresh intake

### Intent-addressed agent/web proposals separate subject identity from navigation
`draft-li-rttp-intent-addressing-01`, published 2026-09-20, defines an `rttp` URI that names a claim of intent toward an identified subject and derives the subject address computationally without registry/name-resolution lookup. It also calls out open-redirect and general-purpose protocol-handler launcher risks. This is an Independent Submission Informational Internet-Draft, not an RFC or adopted Web standard.

**Opportunity:** model agent/on-chain intents independently from transport locator or wallet endpoint: `intent_claim -> subject_identity -> resolution/derivation evidence -> authority -> transaction/effect`.

**Threat:** custom URI/protocol handlers can blur identity, navigation and execution, creating redirect/launcher confusion if an application treats an intent identifier as an executable destination.

**Competitor gap:** blockchain intelligence generally starts at wallet/transaction identifiers and rarely preserves pre-transaction machine intent plus resolution provenance.

**Product idea:** protocol-neutral `intent_ref`, `subject_ref`, `resolution_method`, `resolution_evidence`, and `execution_target` fields. Do not depend on RTTP wire format while it remains an individual draft.

### AIIP/AIID consolidates identity, access, receipt and revocation into one experimental proposal
`draft-sogomonian-aiip-aiid-00`, published 2026-09-20, combines durable AIID principal identity with an agent-only AIIP access plane, signed execution receipts and freeze/revocation controls. The proposal explicitly separates human HTTPS traffic from consequential agent actions. It is Experimental Internet-Draft work, not an IETF standard.

**Opportunity:** retain transport-plane provenance for agent-originated chain actions without assuming HTTP/MCP/A2A/AIIP is the eventual winner.

**Threat:** protocol-specific identity/access claims can be mistaken for authority over a chain effect.

**Product idea:** keep `identity_plane`, `access_plane`, `revocation_state`, `receipt_ref`, and chain-effect evidence as independent nodes so competing agent protocols can map into one evidence graph.

### Standards lifecycle signal
AGTP revision 01 reaches its stated 2026-09-21 expiry. This is lifecycle evidence, not a new protocol release. Continue tracking `published -> revised -> WG adoption? -> replaced/expired -> RFC? -> deployed?`.

## Standards reality
No accepted IETF/W3C generation standard named Web4, Web5, Web6, Web7 or Web8 was identified. RTTP and AIIP/AIID are Internet-Drafts; AGTP expiry is a draft-lifecycle event. Real engineering activity remains agent identity, intent, authority, provenance, revocation and execution evidence.

## Implementation priorities
- Separate intent identity, subject identity, locator/resolution and executable target.
- Preserve access-plane and revocation provenance for agent-originated actions.
- Never equate protocol identity/receipt with valid authority or valid chain state.
- Keep standards lifecycle metadata and cross-chain/source provenance.
