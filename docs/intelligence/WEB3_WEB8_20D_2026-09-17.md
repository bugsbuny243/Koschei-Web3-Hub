## 2026-09-19 fresh intake

### AIN-WRP adds a relationship-state layer before agent interaction
`draft-tanase-ain-authoritative-resolution-00`, published 2026-09-18, proposes authoritative resolution for persistent Agent Identity Numbers plus current operator/authority, endpoint, mandate, restriction, provenance and cryptographic verification information before protected interaction. It explicitly separates identity resolution from credentials, delegated authority, operational eligibility, policy decision and execution. It is an Individual Submission Internet-Draft, not an adopted standard.

**Opportunity:** agent-to-chain evidence can distinguish persistent machine identity from current relationship/authority state before a transaction intent is trusted.

**Threat:** stable identity or successful resolution can be mistaken for permission to perform a current on-chain effect.

**Competitor gap:** wallet/address intelligence generally lacks relationship-specific machine-principal state and evidence-source provenance.

**Product idea:** optional evidence nodes for `persistent_agent_id`, `operator_ref`, `endpoint_ref`, `mandate_ref`, `restriction_ref`, `authoritative_source`, `resolved_at`, and downstream `authority_decision_ref`. Keep the schema protocol-neutral; do not hard-depend on AIN-WRP.

### Standards lifecycle itself is intelligence
Several March 2026 agent/provenance drafts reach their six-month expiry date on 2026-09-19, including ADL, SPICE Intent Chain/Inference Chain, RVP and UPIP revisions unless replaced/updated. This is useful negative evidence: interesting protocol ideas are not automatically converging standards.

**Opportunity:** add standards lifecycle to intelligence objects: `published -> revised -> WG adoption? -> expired/replaced -> RFC?`.

**Threat:** downstream products can mislabel stale Internet-Drafts as current standards and build brittle integrations.

### RFC 10032 is a new crypto artifact, not a Web generation
RFC 10032 (AEGIS AEAD algorithms) was announced 2026-09-19 by the RFC Editor. It is an IRTF/CFRG **Informational RFC**, explicitly not an Internet Standard.

**Opportunity:** crypto intelligence should retain RFC stream/status and deployment/negotiation evidence separately from algorithm identity.

## Standards reality
No accepted IETF/W3C generation standard named Web4, Web5, Web6, Web7 or Web8 was identified in this intake. AIN-WRP is a draft; RFC 10032 is a real Informational RFC but not an Internet Standard. Agentic Web remains the concrete engineering direction, while Web4–Web8 remain non-universal labels.

## Implementation priorities
- Add standards lifecycle metadata, not only a static status enum.
- Preserve relationship-specific machine-principal evidence separately from wallet signature evidence.
- Keep protocol-version/source/provider/cross-chain invariant provenance.
- Keep agent registry/delegation/finality/tool-artifact evidence optional and protocol-neutral.
