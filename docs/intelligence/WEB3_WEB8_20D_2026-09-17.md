## 2026-09-20 fresh intake

### Agent accountability/provenance proposals reach a standards-lifecycle boundary
IETF Datatracker shows `draft-wang-hjs-accountability-01` expiring 2026-09-20. HJS proposes cryptographic responsibility receipts around Judge/Delegate/Terminate/Verify; related JEP models judgment-event accountability, while AAP adds task-to-task causality. These are Internet-Draft proposals, not RFCs or adopted standards.

**Opportunity:** extend agent-originated transaction evidence so accountability is not only `who signed`, but can represent `who delegated -> which agent judgment/task -> which downstream task -> which chain intent/effect -> which receipt`.

**Threat:** an application may mistake a cryptographically intact accountability receipt for proof that the underlying authority/state/transaction was valid.

**Competitor gap:** wallet/address intelligence rarely preserves machine-agent causal provenance plus protocol-status provenance.

**Product idea:** protocol-neutral optional evidence nodes for `judgment_ref`, `task_cause_ref`, `delegation_ref`, `termination_or_revocation_ref`, `effect_ref`, and `accountability_receipt_ref`; never hard-depend on HJS/JEP/AAP wire formats while they remain drafts.

### Standards lifecycle remains a first-class radar signal
The expiry of multiple March agent drafts across 19–20 September reinforces the need to track `published -> revised -> adopted by WG? -> replaced/expired -> RFC? -> deployed?`. Expiry does not invalidate an idea, but it lowers confidence that a specific document/wire format is converging into a standard.

## Standards reality
No accepted IETF/W3C generation standard named Web4, Web5, Web6, Web7 or Web8 was identified in this intake. HJS/JEP/AAP are proposal families in the Internet-Draft process. Agentic identity/delegation/accountability/provenance remain real engineering themes without constituting a standardized Web4–Web8 generation.

## Implementation priorities
- Preserve standards lifecycle metadata and evidence-source provenance.
- Add protocol-neutral causal/accountability references to agent-to-chain intelligence objects.
- Never equate signed accountability evidence with valid authority or valid chain state.
- Keep protocol-version/source/provider/cross-chain invariant provenance.
