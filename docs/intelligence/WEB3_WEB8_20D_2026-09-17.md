## 2026-09-18 fresh intake

### Agent Registry Protocol (ARPA) creates a useful machine-principal discovery/evidence schema
`draft-sankarshan-agent-registry-protocol-00`, published 2026-09-17, proposes an HTTP/JSON registry protocol for agent operator/deployment information, typed relationships, bounded delegated authority, lifecycle state and supporting evidence. It is an Individual Submission with intended Standards Track status, but remains an Internet-Draft—not an RFC or adopted standard.

**Opportunity:** extend agent-to-chain intelligence so a machine principal can carry registry/evidence references separately from wallet identity and transaction authority.

**Threat:** registry discovery can be mistaken for authorization. A record may identify an agent/operator but still be stale, revoked, too broad or unrelated to the exact on-chain effect.

**Competitor gap:** wallet/address intelligence generally lacks machine-principal lifecycle, delegation and evidence provenance. Koschei Web3 can keep these as separate evidence nodes rather than flattening them into a single identity score.

**Product idea:** reserve `agent_registry_ref`, `operator_principal_ref`, `deployment_ref`, `authority_scope_ref`, `lifecycle_state_ref`, `evidence_ref`, `observed_at`, and `standards_status` fields in the agent-to-chain evidence model. Do not make ARPA a hard dependency while it remains a draft.

### Agent add-on provenance becomes relevant to Web3 transaction evidence
The Sep 17 Plugin4Shell disclosure is primarily a Sentinel/software-supply-chain signal, but it has a Web3 consequence: an agent can produce a correctly signed wallet transaction while the software/plugin that generated the intent is not the artifact the user or marketplace believed was running.

**Web3 opportunity:** preserve software/tool provenance for agent-originated transaction intent where available: reviewed artifact identity, resolved runtime artifact identity, agent/tool version and evidence timestamp.

**Threat:** valid wallet signature != trustworthy intent provenance.

## Standards reality
No accepted IETF/W3C generation standard named Web4, Web5, Web6, Web7 or Web8 was identified in this intake. The concrete signal is agent identity/discovery/delegation/evidence and autonomous execution. ARPA is a draft, not a new “Web4/Web5” standard.
