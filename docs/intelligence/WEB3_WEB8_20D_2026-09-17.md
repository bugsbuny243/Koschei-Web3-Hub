# Web3–Web8 20-Day Intelligence — Koschei Web3 Hub

Window: 2026-08-29 → 2026-09-17

## What matters to Web3 Hub

### 1. Protocol-change intelligence is becoming a first-class data source
Ethereum’s current roadmap puts Glamsterdam in Q4 2026 and Hegotá in 2027. Hegotá scoping includes FOCIL and Frame Transactions, while the EF’s September 7 protocol priorities make post-quantum readiness, privacy, state evolution and zkEVM work explicit long-horizon arcs.

**Apply to Koschei Web3:** keep protocol intelligence as a lifecycle, not a headline: `proposal -> client implementation -> devnet/testnet -> activation -> observed chain behavior`. Never mark an EIP/ERC as deployed merely because it exists.

### 2. Post-quantum migration must be visible in chain intelligence
Ethereum targets L1 quantum resistance across execution, consensus and data by December 2029. Account-level signature agility is expected to use native account abstraction/Frames, while consensus cryptography requires fork-level migration.

**Apply:** model PQ state by chain/component: account signature, validator key, data commitment, proof system, wallet compatibility and migration milestone. Preserve algorithm/version provenance.

### 3. Cross-chain failures are usually trust/invariant failures, not broken cryptography
Recent bridge cases reinforce this. Alephium’s September postmortem describes a missing validation in an off-chain re-observation path combined with an eclipse-style attack, causing legitimate guardians to sign valid but unauthorized messages. Symbiosis disclosed a Bitcoin Bridge exploit on September 11 and reported partial recovery.

**Apply:** represent bridge evidence as `source state -> observation/provider -> verification path -> signer/guardian decision -> message -> destination state -> economic invariant`. A valid signature is evidence, not proof that the underlying state transition was authorized.

### 4. Agent-to-chain provenance is becoming important
September IETF drafts explore attenuated multi-hop agent delegation, human delegation provenance, agent identity/resolve/invoke/receipt and per-action execution finality. These are drafts/proposals, not adopted Internet standards, but they expose a durable data-model requirement.

**Apply:** normalize `principal -> agent -> delegation -> tool/service -> intent -> wallet/transaction -> chain state -> effect -> receipt/evidence`. Keep protocol/status metadata so experimental proposals cannot be confused with standards.

### 5. Web4–Web8 reality check
No accepted IETF/W3C generation standard named Web4, Web5, Web6, Web7 or Web8 was identified in this window. Treat those labels as branding/speculation unless backed by a concrete standards artifact and status. The real technical signal is agentic Web, decentralized identity/credentials, delegation, provenance, PQ cryptography and autonomous execution.

## Implementation priorities
- Add protocol-version/activation provenance to intelligence objects.
- Add source/provider provenance to external chain observations.
- Add cross-chain invariant/evidence graph fields.
- Reserve agent principal/delegation/receipt fields in the intelligence schema.
- Add standards-status classification: `ADOPTED | ACTIVE_STANDARDIZATION | DRAFT | PRODUCTION_PROTOCOL | RESEARCH | VENDOR_CLAIM | MARKETING`.
