# Koschei Web3 Hub — Web3→Web8 Monthly Intelligence

**Window:** 2026-09-06 → 2026-10-05  
**Compiled:** 2026-10-06  
**Scope:** Protocol security, agentic Web, identity/delegation, cross-chain infrastructure, post-quantum migration, provenance/evidence, protocol lifecycle. Marketing/price/general crypto news excluded.

## Status taxonomy

- **Production / observed:** live protocol, network, incident or deployment evidence.
- **Standards:** RFC / W3C Recommendation only when actually published as such.
- **Draft / incubation:** IETF Internet-Draft, W3C Community Group, workshop or research proposal; not a standard.
- **Vendor/project claim:** tracked separately from independently observed deployment.
- **Web4–Web8:** no universal IETF/W3C Web4, Web5, Web6, Web7 or Web8 generation standard was identified in this window. These labels remain mostly vision/branding; the real engineering work is in agent identity, authorization, provenance, machine payments, WebMCP/MCP, cross-ledger verification and cryptographic migration.

## Monthly timeline — meaningful findings

### 6–10 Sep
- Ethereum protocol planning/Hegotá: PQ migration, programmable transaction validation, state commitments, fast-finality/privacy tracks. Treat roadmap, implementation, testnet and mainnet as separate states.
- Cloudflare hybrid PQ TLS: X25519+ML-KEM deployment showed crypto migration is an operational compatibility problem, not only an algorithm choice.
- W3C/GS1 agentic commerce workshop: identity, authorization, intent, payment and product-data interoperability became concrete Web architecture topics. WebMCP remained incubation, not Recommendation.
- Aave MCP: DeFi data/action preparation exposed through MCP; unsigned transaction preparation reinforced the need to track `agent → tool → intent → wallet approval → chain effect`.
- Quantus/other PQ-chain experiments and EDHOC-PQ research supplied migration evidence but did not imply whole-system PQ safety.
- WebMCP Community Group work, AIIP and other agent protocol drafts were classified as drafts/experiments, not Web4/Web5 standards.

### 11–16 Sep
- IETF agent-action drafts separated authorization, enforcement, execution and intended result. Web3 evidence model should preserve these as distinct transitions.
- Contestability / request-bound authority drafts highlighted rollback/contest paths and exact-request authority binding.
- Symbiosis bridge incident: implementation/economic invariant failures showed valid cryptography does not guarantee valid cross-chain state.
- Solana/Agave v4.3 rollout: client version, validator stake share, feature gate and activation must be tracked separately.
- Starknet/GMX upgrades: ABI/protocol-version semantics can change agent behavior without a new wallet identity.
- Long Bridge postmortem: a public RPC source could provide non-canonical observations; `RPC response != canonical chain state` became a core provenance rule.
- Safe/Keeper Multicall/Uniswap-v4-hook incident: transitive capability/composability can turn an authorized module into an unexpected effect path.
- GitHub agentic workflow logging reinforced tool-call provenance and credential-lifecycle tracking.

### 17–20 Sep
- New agent drafts on execution handles, state/policy continuity, third-party decision binding and finality-bound revocation: authority freshness must be checked at commit/finality time.
- Agent Trust Profile: identity → principal binding → delegation → authorization → provenance → revocation became a useful evidence graph, but remained draft work.
- ARPA Agent Registry Protocol: discovery/registry data must not be treated as current authorization.
- Plugin4Shell disclosure: reviewed artifact identity must match resolved/materialized/runtime-loaded artifact.
- RFC 10032 AEGIS: real Informational RFC; status must not be inflated to Internet Standard.
- AIN-WRP and related drafts: persistent identity, credential, proof-of-control, delegated authority, eligibility and execution are distinct.
- HJS/JEP/AAP accountability drafts: signed accountability receipts do not prove safe effect.

### 21–24 Sep
- RTTP intent addressing: intent/subject resolution introduced a new provenance path `intent → subject → resolution → target → effect`; Internet-Draft, not RFC.
- AIIP/AIID experiments combined identity, access, receipt and revocation; useful model, not standard.
- Agent-security market moved toward model→MCP/tool→API/effect graphs and runtime identity enforcement.
- ECB Pontes production signal: DLT asset settlement can connect to conventional central-bank-money settlement; cross-ledger evidence must model both legs.
- MCP ecosystem measurements showed weak declared authentication across a large server corpus; trust posture is time-varying.
- Bifrost AI gateway vulnerability reporting reinforced that verification ordering matters: a control that occurs after side effects is not a control boundary.
- Proof-of-Control / execution-evidence work reinforced evidence semantics.
- Solana Alpenglow public-testnet phase: target finality, client support and mainnet activation are separate facts.
- RGB 0.11.1: client-side validation means base-chain data alone may not reconstruct asset state.
- Tezos Quantumnet: PQ migration must cover accounts, consensus/DAL/randomness dependencies, not just signatures.
- AINS agent discovery revision: discovery metadata is not action authorization.
- LFDT cross-ledger lab work and ETSI entropy/QRNG guidance strengthened state-proof and entropy-provenance models.

### 25–28 Sep

- Several agent-protocol drafts reached expiry/revision boundaries. Add lifecycle: `published → revised → adopted? → expired/replaced → RFC? → deployed?`.
- AAuth/AIRS family: agent identity, handle resolution, registry provisioning and resource authorization are separate layers; drafts, not standards.
- Agent Network Protocol experiments (AIP/AITP/ANS/ADP) reached draft lifecycle boundaries; do not label them an “Agent Internet standard”.
- Runtime containment research showed declared sandbox policy and actual network/runtime enforcement can diverge.
- NVIDIA Open Agent Safety/OpenShell/Sentry direction: agent containment is moving across software runtime and hardware observation layers.
- Zano recovery event: source-chain rollback cannot automatically reverse already-settled external effects. Track canonical history and external settlement separately.
- MCP research separating proposal/dry-run from execution reinforced explicit effect boundaries.

### 29 Sep – 2 Oct
- Chainlink CCIP 2.0: verifier/finality/executor choices can vary per cross-chain flow; protocol-name-level risk scores are insufficient.
- Live Agent over MoQ draft: transport/turn state, cancellation and authoritative tool effects can diverge; draft, not RFC.

- AAT audit-trail draft: tamper-evident logs do not prove truthful outcome or authorized effect.

- Chainlink Fulcrum: cross-chain now includes agreement state, collateral/data, public/private ledgers, cash leg and settlement finality—not only token bridges.

### 3–5 Oct

- X.509 agent identity profile draft: certificate validity is not current action authority.

- AITLP lifecycle boundary: an IETF-hosted individual draft is not an IETF standard.

## Web3 Hub product requirements derived from the month

1. **Protocol Lifecycle Radar** — separate announcement, implementation support, validator/client adoption, feature activation, observed capability and finality.
2. **Cross-Layer Evidence Graph** — `source state → observation provider → canonicality/finality → verifier → message/adapter → destination/external effect → receipt`.
3. **Agent-to-Chain Provenance** — `identity → delegation → intent → tool/MCP → wallet approval → tx → state effect → evidence`.
4. **Cross-Chain Trust Composition** — score effective verifier/finality/executor configuration per flow, not only bridge brand.
5. **Economic Invariant Continuity** — reconcile intent amount, deposits, adapter balances, accounting, withdrawals and destination receipts.
6. **Capability Stage Model** — WATCHING / DEPOSIT / POOL / SWAP / WITHDRAW / FINALITY_VERIFIED rather than one boolean “supported”.
7. **PQ Migration Radar** — component-level algorithms, trust anchors, key lifecycle, consensus, transport, bridge/admin dependencies, deployment and evidence grade.
8. **Credential/Identity Provenance** — issuer, holder, disclosure, freshness/revocation, verifier and resulting permission/effect.
9. **Artifact/Dependency Provenance** — requested → resolved → materialized → verified → runtime-loaded artifact.
10. **Standards Status Engine** — RFC/W3C Recommendation vs WG draft vs individual I-D vs Community Group vs research/vendor/marketing label.

## Canonical evidence principles

- `valid signature != valid state transition`
- `RPC response != canonical chain state`
- `identity != authority`
- `discovery != authorization`
- `protocol support != activated capability`
- `testnet active != mainnet active`
- `rollback != reversal of external settled effects`
- `PQ primitive present != end-to-end PQ system`
- `tamper-evident receipt != truthful/safe effect`

## Current architecture direction

`Human/Org → Agent Identity → Credential/Delegation → Intent → Tool/MCP/A2A/WebMCP → Observation/Canonical State → Policy/Authority → Transaction/Protocol Action → Cross-System Effect → Receipt/Proof → Finality/Reconciliation`

Koschei Web3 Hub should provide the blockchain/protocol/evidence intelligence for this chain; it should not collapse these states into a single “safe/unsafe” flag.
